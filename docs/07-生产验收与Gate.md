## 1. Gate 原则

- 生产环境可启动不代表已通过安全验收。
- CI 通过不代表业务流程、数据库、部署拓扑或客户资料安全已通过。
- 文件存在不代表功能可用；代码路径存在不代表部署环境已启用。
- 测试环境、合成资料和模拟回单不得被描述为真实客户交易。
- 每条结论必须绑定确切 commit SHA、测试环境、测试时间、命令/步骤、预期结果、实际结果和证据位置。
- 未核验的能力必须标为 NOT_VERIFIED，不得默认为 PASS。
- 未获明确授权，不执行生产发布、公网开放、真实客户导入或破坏性数据迁移。

## 3. 测试矩阵

### 3.1 构建与静态检查

- 安装锁定依赖。
- 执行 npm run typecheck。
- 执行 npm run build。
- 执行全部单元测试与集成测试。
- 检查依赖漏洞、秘密扫描和不必要的敏感日志。
- 保存测试命令、退出码、摘要和对应 commit SHA。

通过条件：命令真实执行成功；不能用旧日志或其他 SHA 的结果代替当前候选。

### 3.2 身份与授权负向测试（P0）

必须覆盖：
- 未登录访问内部页面和敏感 API。
- 登录后使用错误角色执行受限动作。
- 用户 A 读取、修改或签署用户 B 的资源。
- 伪造、过期、撤销、截断或重放 Token。
- 通过直接 HTTP/API 调用绕过前端按钮限制。
- 尝试通过对象 ID、查询参数或请求体切换客户归属。
- 会话注销后继续重放旧凭证。
- 对敏感端点进行超限请求。

通过条件：服务端拒绝未授权操作，不泄露敏感正文；拒绝行为留有不含秘密的审计记录。

### 3.3 合同与签署

- 生成合同草稿并核对服务范围、金额、币种、期限和版本。
- 检查客户与工作人员的签署顺序及授权。
- 测试签署后重复提交、并发提交和旧版本签署。
- 验证签署内容与最终合同版本绑定。
- 验证链接过期/撤销后不能继续签署或读取。
- 检查签署证据、时间、操作者和合同版本是否可追溯。

通过条件：重复和并发操作不会导致状态错乱；已签版本不可被静默覆盖；对外明确签署效力边界。

### 3.4 收款与订单门禁（P0）

至少覆盖：
- 订单金额为 0 或非法金额。
- 未签约即尝试开工。
- 未到账、部分到账、错误金额、重复回单和重复核销。
- 已到账但未完成核销。
- 月度预收不足、阶段首款不足、按单定金不足。
- 尾款未结清即尝试交付。
- 交付物未完成、复核未通过即尝试交付。
- 退款、冲正、撤单、合同变更和争议。
- 两个并发请求同时登记同一笔实收。

通过条件：所有门禁在服务端执行；数据库最终状态、应收和实收记录一致；退款和冲正可追溯。

### 3.5 资料、工作底稿与交付

- 验证资料来源、版本、授权、客户归属和缺失项。
- 验证同一文件新版本不会覆盖旧证据。
- 验证工作底稿能够回指原始资料并重现核对口径。
- 验证机械完整性检查与专业复核的责任分离。
- 验证交付包版本冻结、客户确认、纠错和再次交付。
- 验证客户退出后的访问撤销、保留与销毁规则。

通过条件：交付物、证据、复核意见和最终版本之间有稳定关联。

### 3.6 备份、恢复与运行

- 确认生产环境数据库、文件和配置的备份范围。
- 在隔离环境恢复数据库与必要文件。
- 核对恢复后的客户/订单/合同数量、金额和关键状态。
- 测试服务启动、健康检查、异常告警和回滚。
- 验证真实监听地址及反向代理/防火墙配置。
- 检查日志是否泄露凭据、客户资料或原始财务内容。

通过条件：恢复可复现、数据核对一致、回滚步骤可执行；不允许仅以“备份任务显示成功”作为恢复通过证据。

## 4. 必须完成的端到端场景

使用专门的脱敏测试客户，按顺序完成：

1. 录入线索并记录公开来源。
2. 资格筛选与预约诊断。
3. 生成风险清单。
4. 确认付费方案、服务范围及授权。
5. 创建合同并完成双方确认。
6. 创建订单及应收计划。
7. 证明未付款、部分付款、重复回单均不能错误开工。
8. 在测试环境登记已核实的测试到账并完成核销。
9. 创建项目、任务、资料清单和交付时间。
10. 登记资料、编制底稿、记录差异并完成复核。
11. 生成交付包、记录接收确认。
12. 证明未结清约定款项、交付物缺失或复核失败时不能违规标记完成。
13. 执行收尾对账、资料归档和月度复盘。
14. 测试退款/冲正、项目暂停、纠错和重新交付。
15. 验证跨客户访问、过期 Token、重复请求和权限撤销。
16. 完成备份恢复与部署回滚演练。

每一步必须记录测试数据标识、预期结果、实际结果、证据引用及 PASS/FAIL/BLOCKED。

## 5. 发布决策

### PASS
所有 P0 控制、关键 E2E 场景、恢复演练和部署版本核验通过；不存在未处置的高危风险；小 m 已独立复核证据。

### PARTIAL_PASS
部分功能和测试通过，但仍有非阻断项。必须明确未通过范围，不得宣称整体生产验收通过。

### BLOCKED
身份/授权、客户隔离、收款门禁、数据完整性、备份恢复或生产版本一致性存在未解决的 P0 风险；或关键证据缺失。

任何状态均不自动授予公网开放、品牌发布、客户资料导入、生产部署或支付通道启用权限。此类动作仍需委托人当次明确授权。
