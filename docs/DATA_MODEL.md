# DATA_MODEL

| 表 | 作用 | 迁移 |
|---|---|---|
| `fin_contract` | 确认书正文、客户 token、工作人员 token、`expires_at`、`revoked_at` | 0002，0003 加两列 |
| `fin_channel` | 通道号与加密后的密钥 | 0002 |
| `fin_audit` | 动作、角色、资源哈希、是否成功。不记口令、密钥和完整 token | 0003 |
| `fin_rate` | 登录失败和无效链接的计数 | 0003 |
| `fin_desk` | 一份全所台账，带版本号。版本大于 0 时，它高于浏览器缓存 | 0003 |
| `fin_idem` | 同一次保存内容的重复提交 | 0003 |
| `fin_journal` | 实收增减的借贷分录。原分录不改 | 0004 |
| `fin_period` | 已锁定的会计期间 | 0004 |
| `fin_inquiry` | 访客留下的需求。联系方式不进浏览器缓存 | 0005 |

确认链接默认 14 天。撤销后立即失效。旧行在执行 0003 时，从当时的 `updated_at` 起算 14 天。

台账 JSON 里仍有客户联系方式。这不是加密字段。没有授权和备份演练之前，不要把真实客户名单导进去。

三份存储各管一段：`localStorage` 只缓存当前已登录会话；`fin_desk` 是内部台账的已保存版本；`fin_contract` 是已经发出的确认书。没有 `?t=` 的 `/sign` 不读取本地台账。访客需求进 `fin_inquiry`，不进 `localStorage`。

回滚 0003：先备份，再按 `RELEASE_AND_ROLLBACK.md` 删除新表和新列。不要直接删库。`0004` 和 `0005` 也还没有在生产库执行。
