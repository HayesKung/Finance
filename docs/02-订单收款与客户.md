# 订单、收款、客户与项目

这是服务流程，不是支付通道。

## 端到端

1. 名单里只记公开线索。
2. 升为客户，或直接建客户档。客户下面挂他的出口票或海外项目。
3. 诊断只出风险清单，不在这一步开工。
4. 建草稿订单：客户、可选项目、产品、收费方式、财务人员确认后的金额。系统不自动报价。
5. 生成收款计划。
   - 按单：定金 50%，尾款 50%。
   - 月度：当月费用 100% 预收。
   - 阶段：首段 50%，其余交付前结清。
6. 定金、当月预收或首段费用记到“已收”之后，才允许改成执行中。
7. 交付物按产品勾完，并且每一笔都收齐，才允许改成已交付。
8. 已交付不能直接取消。草稿不能直接标已交付。
9. 复盘和案例公开仍要客户同意，不在订单状态里自动公开。

金额为 0 的订单不能生成收款计划。不接受先做后看。

## 不做什么

- 不发起扣款，不接支付网关。
- 不登记、不代收客户自己的项目回款、退税款或贷款。
- 这里的“已收”只表示服务费是否进了服务方自己的账户，由财务人员本人登记。

规则在 `src/lib/finpivot/flow.ts`，页面不能绕过。

## 异常

真实运营前还要盖住这些情况：部分付款、错误金额、重复回单、未核销到账、逾期、退款、冲正、合同范围变更、项目暂停和恢复、交付纠错、争议升级。每一种都要有责任人、状态、证据和审计，不能靠改掉原来的记录处理。

- 服务端要重新检查开工和交付条件。页面上的按钮不算数。
- 重复请求和并发保存不能记成两笔实收或两次签署。
- 客户申报已转账、付款截图、选了一种支付方式，都不是服务方到账。
- 已签确认书、已核销的实收和已交付版本如果要改，留下轨迹。原分录不改，冲正另记一笔。

银行回单号的唯一约束在 `migrations/0006_receipt.sql`。这个文件在仓库里，生产库还没有执行。台账里的实收仍然走已保存的 `fin_desk` 和 `fin_journal`。
