# SECURITY_AND_PRIVACY

已在代码里做到的：

- `/staff/login` 是工作人员入口。内部路由加载前没有会话会转到登录页，不先渲染台账。
- 更改状态的服务函数核对来源主机。登录失败次数在同一事务里计数。
- 支付密钥接口不再接受匿名调用。保存值用独立的 `FINANCE_DATA_KEY` 加密。这把密钥缺失时保存失败。
- 确认链接有期限和撤销。签署用行锁，已签署的内容不会被后到的请求改掉。签署后的服务费和账户不会被另一次保存改写。
- 客户声明已转账不会记成实收。在线支付回调一律拒绝入账。实收增加要有回单号、不超过应收，并生成借贷平衡分录。冲正另记，不改原分录。
- 审计记的是哈希，不是 token 原文。通道密钥、撤销、签署和台账保存如果审计写不进去，事务回滚。
- `robots.txt` 只是提示，不是访问控制。

- 没有确认链接的 `/sign` 不打开本地确认书、客户或收款账户。
- 新订单不能直接写成执行中或已交付。重复编号、非法状态、没有订单的收款行、把收款行改到别的订单，保存时都会拒绝。
- 支撑人员不能改已有私人联系方式，也不能改收款账户。
- 访客需求写入 `fin_inquiry`。这张表还没有在生产库执行。

还没有做到、因此不能称为生产安全：

- 本轮没有从外部复测生产端口和反向代理，也没有启用 HSTS。域名尚未批准。
- 客户联系方式在 `fin_desk.body` 里仍是明文。
- 没有备份恢复演练，`0004_journal.sql` 和 `0005_inquiry.sql` 还没有在生产库执行。
- 已暴露的工作人员口令必须由负责人在服务器上轮换。本轮没有读取、写入或复述口令。
- 没有文件上传和销毁流程。
- 会话固定 12 小时，没有按人拆开的账号，也没有设备清单。两人仍共用角色口令。
- 持牌电子签和微信/支付宝扣款没有接通。`providerLive` 是 false。
- 限流在不信任 `X-Forwarded-For` 时，可能把代理后的所有人算成同一个地址。只有确认代理可信、并且由代理覆盖转发头，才设置 `FINANCE_TRUST_PROXY=1`。

口令、`DATABASE_URL`、`FINANCE_SESSION_SECRET` 和 `FINANCE_DATA_KEY` 只放在服务器的 env 文件。不要写入仓库、任务卡或聊天。
