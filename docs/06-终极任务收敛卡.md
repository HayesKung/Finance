## 1. 北极星与完成定义

让一名财务负责人 + 一名支撑人员可以安全、合规、可追溯地完成：

线索 → 诊断 → 付费方案 → 资质/授权审核 → 合同 → 预收 → 项目 → 资料 → 工作底稿 → 复核 → 交付 → 对账 → 复盘 → 续约/转介绍。

不以页面数、代码行数或文档数量为完成标准。只有关键业务链路、异常场景、安全负向测试、数据恢复和生产版本核验均有证据，才可宣告通过。

## 2. 不可变红线

1. 先审计现状，再做增量改造，不无故重写技术栈。
2. 不擅自修改 Drive 已确认的价格口径、服务范围和红线。
3. 不虚构客户、成交、收入、案例、资质、交付或测试结果。
4. 不经手客户项目资金，不垫资、不入股、不做资金过桥。
5. 对代理记账、税务申报、审计、法律意见等工作先核实适用资质与执业要求；超出能力或资质范围时升级或转介。
6. 不冒用海哥或财务负责人的身份对外联系、报价、签约或发布内容。
7. 未获授权，不开放公网、不发布官网、不购买域名或付费服务、不执行生产部署。
8. 不以 noindex、隐藏导航、前端状态或随机 URL 代替服务端鉴权。
9. 密钥、Token、Cookie、验证码、客户隐私和银行账户不得进入 Git、任务卡或普通日志。
10. 生产数据迁移/修复前必须备份并对账；变更必须有回滚方案。
11. 未经核验的外部代码不得直接合入生产。
12. 自动化与 AI 默认只读或建议模式；对外发布、签约、正式专业结论及资金相关动作须由授权人员确认。

## 4. WP1：身份、权限、隐私与密钥安全（P0）

### 工作内容
- 落地真实服务端认证、会话生命周期、注销和过期处理。
- 定义财务负责人、支撑人员、客户及只读审计角色。
- 每个敏感 API 都执行身份、角色、资源归属和操作权限检查。
- 对内部工作台、客户入口、合同资源进行服务端隔离。
- Token 具备足够随机性、有效期、撤销、限流和访问审计。
- 对合同签署和其他关键写操作实施并发保护。
- 明确客户资料的加密、访问、导出、保留与销毁规则。
- 密钥最小权限、受控保存、轮换及访问审计。

### 验收
- 未登录、无权角色、跨客户资源、失效 Token、被撤销链接和恶意参数均被拒绝。
- 不能通过直接调用 API 或修改前端状态绕过权限。
- 普通日志不含凭据和不必要的敏感正文。
- 备份与恢复有可复现测试。

## 5. WP2：业务状态机与数据持久化（P0）

### 工作内容
- 明确 Lead、Client、Contract、Order、Receipt、Project、Task、Document、Workpaper、Review、Deliverable、AuditEvent 等对象及关系。
- 统一服务端状态转换与校验。
- 对关键写操作实施数据库事务、版本控制、幂等和并发冲突处理。
- 制定数据库迁移、索引、约束、备份和回滚策略。
- 明确浏览器本地状态和服务端正式记录的权威边界。
- 迁移数据前做备份、记录数和金额对账。

### 验收
非法状态跳转失败；并发更新、重复提交和事务回滚不产生重复订单、重复收款或状态不一致。

## 6. WP3：合同、收款与对账（P0）

### 工作内容
- 报价由财务负责人确认，系统不得自动对外报价。
- 合同范围、期限、价格、版本、签署及授权记录可追溯。
- 保留按单定金、月度预收、阶段首款等已确认规则。
- 区分客户申报付款、真实到账、核销及未核销款。
- 处理部分付款、金额不符、重复回单、逾期、退款、冲正、合同变更和争议。
- 订单开工及交付门禁在服务端执行。
- 核验签署记录的法律效力边界；需要可靠电子签名时使用适当的持牌服务。

### 验收
没有满足合同/授权条件及首款到账要求不能开工；不满足约定的交付、复核和付款条件不能违规完成订单；退款和冲正保留审计轨迹。

## 7. WP4：专业服务交付内核（P1）

分别为以下服务建立 SOP、资料清单、底稿模板、复核表、交付包和端到端测试：

- 出口财务包：单证核对、收汇核对、退税资料整理、差异与风险提示。
- 海外项目财务托管：预算/实际成本、现金流、进度款、应收账龄、结算证据和月度财务包。
- 结算与清欠专项：合同/签证/结算/发票/付款关联、逐笔对账和证据索引。

统一实现：
- 文件来源、版本、哈希、授权和完整性检查。
- 工作底稿、差异、编制人、复核人、签发状态。
- 交付版本冻结、客户确认、纠错和复盘。
- 工时、成本、产能与任务阻塞统计。

验收：三类服务均可用真实或明确标注的合成资料走完完整流程；合成数据不得当作真实客户成果。

## 8. WP5：资质、授权与保密（P1）

- 建立客户准入、服务能力、资质核验及专业升级规则。
- 明确服务范围、授权联系人、资料处理目的与保密义务。
- 建立案例公开的书面授权、脱敏与负责人批准流程。
- 对利益冲突、缺失资料、异常金额和争议性结论建立升级机制。
- 明确资料保留、客户退出、访问撤销和销毁流程。

验收：不满足必要资质、授权或资料条件时，系统阻断对应服务进入执行状态。

## 9. WP6：获客、经营和续约（P1）

- 建立公开来源目标名单、诊断预约、风险清单、付费方案、报价、签约和失单漏斗。
- 记录每一步负责人、下一步、截止日期、结果和未转化原因。
- 统计真实签约额、到账、应收、履约、工时、成本和毛利。
- 建立续约、逾期应收、资料补充、交付和复盘提醒。
- 追踪首期 100 家目标、20 家诊断邀约、2 个试点目标，但只按证据更新实际完成状态。

验收：每个指标可追溯至具体业务记录；草稿、目标或口头报告不能计为完成。

## 10. WP7：部署、监控与恢复（P1）

- 明确开发、测试和生产配置隔离。
- 固化构建、类型检查、自动化测试、迁移检查和发布流程。
- 保持预期的回环监听约束，禁止在认证完成前扩大暴露面。
- 建立健康检查、错误日志脱敏、异常告警和运行手册。
- 执行备份恢复、发布回滚及部署版本核验。
- 所有生产变更须获得当次明确授权。

验收：可重复部署、可验证健康状态、可恢复数据、可回滚失败发布，实际部署版本与核验 SHA 一致。
