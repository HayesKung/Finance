# 本地构建

仓库原先只有业务源码。缺这些文件时，`npm install` 之后也编不起来：

- `package.json`、`vite.config.ts`、`tsconfig.json`、`.gitignore`
- `src/client.tsx`
- 被引用但不在仓库里的四个模块：`src/lib/error-component.tsx`、`src/lib/preview-path-prefix.ts`、`src/lib/auth/provider.tsx`、`src/components/preview-host-bridge.tsx`

## 版本

锁定 `@tanstack/react-start@~1.168.60`，配 `vite@^8`。不要升到 1.169 再按旧教程找入口。

- 1.169 要求 Vite 8 或更高。1.168.60 在这份锁定里已经和 Vite 8 一起用。
- 1.169 没有 `app.config.ts` 这个入口。不要补一个空的配置文件指望它被读到。
- `StartClient` 从 `@tanstack/react-start/client` 引入。`src/client.tsx` 就是这个入口。
- 低于 1.168.60 的 Start 有已公开的漏洞，不要为了迁就旧教程往回降。

## 产物不自己监听

Nitro 的 `node-server` 产物在导入时才会监听，而且默认主机可能不是回环地址。只导出 `fetch` 的 `dist/server/server.js` 则完全不监听。`listen.mjs` 固定 `127.0.0.1`：产物会自己监听时只加载它；产物只有 `fetch` 时在本机包一层 HTTP。`HOST` 不是 `127.0.0.1` 时直接退出。

不要把这个适配层命名为 `server.mjs`。Nitro 会把项目根目录的 `server.mjs` 当成服务入口，并要求它有 default export。本地排错时看到的 `MISSING_EXPORT default` 就是这个名字撞上了。

`npm run start` 只在 Linux 上做回环核对，因为它要读 `/proc/net/tcp`。Windows 和 macOS 没有这个文件，`npm run start` 会直接退出。这不是装错依赖。`npm run dev` 不走这层核对。端口若绑在 `0.0.0.0` 或其它非回环地址，进程也直接退出。不要改成直接执行 `.output/server/index.mjs`，那样会绕过这层核对。

## 不是裸机口径的路径

`/__grok/` 是预览宿主自己的 PWA 清单和图标，不是这个仓库的生产路径。裸机构建不要引用 `/__grok/manifest.webmanifest` 和 `/__grok/icon-180.png`，也不要把预览宿主的 `__grok` 目录拷进 `public/`。站点图标用 `public/favicon.svg`。

分享卡片先不做。`public/og.jpg` 在仓库里，但品牌名还没确认，页面不写 `og:` 或 `twitter:`。

## 鉴权

`AuthProvider` 仍然只是透传，不是访问控制。工作人员入口是 `/staff/login`。内部页在加载前调用 `whoami`，没有会话就转到登录页。口令、`FINANCE_SESSION_SECRET` 和 `FINANCE_DATA_KEY` 只放在服务器环境变量里。`FINANCE_DATA_KEY` 缺失或短于 32 位时，保存通道密钥会失败，不会回退到会话密钥。

持牌电子签和在线支付都还没有接通。保存密钥只表示密钥已加密存放。客户点击“已转账”不会记成实收。

生产发布、域名和 HTTPS 证书不在这次本地修改里完成。监听地址仍然只能是 `127.0.0.1`。不要改 nginx。同一台机器上还有别的生产服务。

确认书、审计和已保存的台账在 Postgres。浏览器里的副本不是主账。实收变动还要有 `fin_journal`，对应迁移是 `migrations/0004_journal.sql`。
