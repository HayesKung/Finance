# ARCHITECTURE

状态：IN_PROGRESS。内部页有服务端会话门，不是生产验收。

浏览器上的对外页（`/`、`/ask`、`/sign`）不要求工作人员登录。`/staff/login` 是登录页。`/os`、`/clients`、`/orders`、`/pipeline`、`/playbook`、`/templates`、`/diagnose` 在路由加载前检查 `fin_staff` cookie，没有会话就转到登录页。Cookie 由 `FINANCE_SESSION_SECRET` 签名，12 小时过期，HttpOnly。生产环境默认 `Secure`。更改状态的服务函数还核对 `Origin` 和 `Host`。

两个角色：

- `owner`：财务负责人。可以保存支付密钥、撤销确认链接、核对实收、保存台账。
- `support`：支撑人员。可以发确认书和看台账，不能保存支付密钥，不能撤销链接，不能核对实收。

口令只放在服务器环境变量里。程序不保存口令，也不接受由浏览器自己声明角色。登录失败次数在数据库里加行锁后计数。保存通道密钥、撤销确认书、签署、保存台账这些写入，审计失败会把整笔事务回滚。

Postgres 是确认书、审计、限流、分录和已保存台账的正式存储。浏览器本地台账不是主账。保存时服务器按上一版重新检查开工、实收和复核，不信任浏览器传来的“已通过”。实收变动要能生成借贷平衡的分录，写进 `fin_journal`。原分录不改，冲正另记一笔。`migrations/0004_journal.sql` 还没在生产库执行。

支付密钥写入前用 AES-256-GCM 加密，密钥来自 `FINANCE_DATA_KEY`。没有这把独立密钥时拒绝保存，不回退到会话密钥。接口只返回“是否已配置”，不把密钥发回浏览器。`providerLive` 固定为 false：微信、支付宝、持牌电子签都还没有正式下单或签署调用。客户声明的转账方式不是实收。

未做：生产主机本轮没有重新部署。域名、HTTPS 和 HSTS 还没有获批。公网是否仍能转到回环端口，本轮没有复测。
